# EXP-024 — Phase 3 PWR ON + P2_0 HIGH-LOW-HIGH

## Hypothesis

Po `EPD_PWR` ON (P0_0=0) hardware reset na kandidátu P2_0 (`HIGH → LOW → HIGH`) je při isolation workflow bezpečný pro MCU. P1_3 se po uvolnění resetu může změnit; 0→1 / 1→0 po H-L-H je silná evidence kandidáta BUSY. Pokud P1_3 zůstane 0, výsledek je INCONCLUSIVE/NO RESPONSE, ne „pin není BUSY“.

## Firmware

`v0.4c_reset_hlh` on `research/gu140`

První obrazy (v0.4b klon + P2SEL, pak klon bez P2SEL) daly UART garbage od prvního bytu. A/B: stejný workflow, `v0.4b_pwr_only` = čistá UART. Finální obraz: kompaktní log + SDCC `--nooverlay` + `delay` ve static DATA. Žádné SPI, DC/CS, `0x00`/`0x0E`. P2SEL nedotčen. P0_2 nedotčen. P2_3/P2_4 nedotčeny.

## Exact HW state

DEV tag only. Debugger při runtime fyzicky odříznutý (GPIO27 dh, GPIO21 dh). GPIO17 dl během capture. Konec: idle (vše dh). UART CP2102 RXD+GND beze změny.

## GPIO/debug relay state

Flash: `ov26-relays.sh attach`. Runtime: 27 dh, 21 dh, 17 dl. End: idle.

## Build / flash

SDCC 4.2.0 `./build_one.sh v0.4c_reset_hlh` (`--nooverlay` jen tento target). Hex ~3.0K. `cc-tool -t` CC2510, erase+write+verify OK.

## Test procedure

1. TAG OFF 2 s
2. UART 115200 8N1, timeout 32 s
3. TAG ON (true POR, debugger isolated)
4. Sequence: PWR OFF sample → PWR ON → PRE RST P1_3 → RST H → RST L → RST H2 → S 01..05 → heartbeat
5. TAG OFF

## UART (final image)

```text
OpenVusion GU140 EXP-024 v0.4c RST
RESET_CAUSE=01
PRE PWR_OFF BUSY=0
PRE RST BUSY=0
RST H BUSY=0
RST L BUSY=0
RST H2 BUSY=1
S 01..05 BUSY=1
DONE
HB 00..13 BUSY=1
```

1× `EXP-024`, 1× `DONE`. Capture: `captures/ov26_exp024_por.bin`

## Observations

- MCU: jeden banner, `RESET_CAUSE=01` (EXTERNAL_RESET_N, stejná rodina jako isolated POR), heartbeat 00–13, žádný re-banner → **žádný reset storm** při P2_0 H-L-H v isolation
- P1_3 před resetem (PWR OFF i PWR ON): `0`
- P1_3 během RST H a RST L: `0`
- P1_3 ihned po RST H2 (uvolnění resetu): `1`, drží `1` po celý zbytek capture (~20 s)
- To je přechod **0→1 vázaný na dokončení H-L-H**, ne statická nula
- Napětí EPD rail nebylo měřeno

## Result

**PASS** (MCU + UART continuity + H-L-H dokončen, isolated)  
**STRONG EVIDENCE** (P1_3 reaguje na EPD reset po PWR ON → kandidát BUSY)  
Identita P1_3 = CoG BUSY a polarita ready=HIGH **ještě nejsou OVĚŘENO** (žádný command, krátký busy pulse po H2 mohl ujít)

## OVĚŘENO

- Isolated P2_0 H-L-H po P0_0=0: MCU nestormuje
- P1_3: `0` před/během pulzu, `1` po uvolnění resetu, UART kontinuita
- Historický storm z EXP-006/v0.3e se za GPIO27+21 dh **nereprodukoval**

## REFERENCE

P2_0 = EPD_RESET, P1_3 = BUSY (GL340 + FPC). Pervasive iTC: L=busy, H=ready. Po resetu HIGH je slučitelné s idle ready.

## HYPOTÉZA

CoG po HW resetu drží BUSY ready (HIGH) dokud nepřijde command. Krátký LOW pulse po H2 mohl být kratší než okamžik vzorku `RST H2`.
