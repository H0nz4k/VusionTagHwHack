# EXP-041 — UART control after post-cc-tool garbage

## Hypothesis

A UART-only image (`v0.6c`, no P0_4/P0_6) still prints a clean banner. Distinguishes I2C code vs CP2102 capture path.

## Firmware

`v0.6c_nfc_uart`. Same clock+uart+delay_crude as v0.5a. `--nooverlay`.

## UART

Isolated flash immediately after `cc-tool`: **FAIL** (137 B high-bit garbage).

Recapture **without** programmer (`ov26-uart-recap.sh`): **PASS**

```text
OpenVusion GU140 EXP-041 v0.6c NFC UART
RESET_CAUSE=01
HB 00
HB 01
HB 02
DONE
```

ASCII_RATIO 0.977.

Known-good `v0.5c` hex: same pattern (isolated FAIL, recapture/sweep 115200 PASS). Baud sweep: only 115200 decoded `EXP-036`.

## Result

**PASS** on recapture. Isolated-flash UART immediately after debugger USB cycle is **not** a reliable decoder. Firmware was fine.
