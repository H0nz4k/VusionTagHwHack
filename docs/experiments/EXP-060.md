# EXP-060 — RF PTHRU via session 0xEC, MCU polls I2C SRAM 0xF8

## HYPOTÉZA

I2C write `0xFE` NACK (058/059). RF WRITE session stránky `0xEC` s `NC_REG |= 0x40` zapne PTHRU. Pak WRITE `0xF0` `OVMB` a MCU v pollu `0xF8` uvidí `4F 56 4D 42`.

## VSTUPNÍ STAV

DEV, attach, isolated I²C. Firmware `v0.11d` jen čte SRAM. TWN4 přiložen (UID shoda).

## JEDNA HLAVNÍ ZMĚNA

PTHRU z RF (`0xEC`), ne z I2C `0xFE`. MCU poll `0xF8`.

## OČEKÁVANÝ VÝSLEDEK

Host: `ec_written`, `NC_REG_after` má bit 0x40, `written` F0. UART: některý `SRAM 4F 56 4D 42`.

## SKUTEČNÝ VÝSLEDEK

UART (`captures/nfc/ov26_exp060_por.bin`): 12× `ACKAB=01 SRAM 00 …`, `DONE`. Žádné `OVMB`.

TWN4 (UID `04367F5A2D7280`, PWD_AUTH PACK `00 00`):

```text
session 19 00 F8 48 08 01 01 00  NC_REG=25
ec_written false  WRITE 0xEC NAK 0x0
written false     Tag neodpověděl na A2  (WRITE F0)
f0 ERR            30 F0 timeout
```

## KLASIFIKACE

**FAIL** — RF Type-2 WRITE session `0xEC` NAK. Bez PTHRU WRITE/READ `0xF0` taky neprojde. MCU I2C SRAM read pořád PASS (nuly).

## ZÁVĚR

PTHRU nejde zapnout ani I2C `0xFE` data, ani RF `0xEC` WRITE `0xA2`. Session z RF **číst** jde (FAST_READ EC–ED). SRAM mailbox z RF je bez PTHRU neplatná adresa.

## DALŠÍ KROK

Neopakovat A2 na `0xEC` ani I2C write `0xFE`. Další větev: **SRAM_MIRROR** v config `0xE8` (persistent, po PWD_AUTH, vratný zápis zpět `19 00 F8 48`) — SRAM v user pages, MCU čte `0xF8`. Nebo NXP I2C session write formát (16 B / jiný Sr).
