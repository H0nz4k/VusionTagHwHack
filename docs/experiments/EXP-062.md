# EXP-062 — I2C write config block 0x3A (SRAM_MIRROR)

## HYPOTÉZA

RF WRITE `0xE8` NAK kvůli `REG_LOCK` NFC. I2C config `0x3A` je jako EEPROM `0x01` (ACK). Zápis `1B 00 40 48` zapne SRAM_MIRROR.

## VSTUPNÍ STAV

EXP-061 FAIL. DEV, isolated, TWN4 off při I2C write. UART znovu OVĚŘENO.

## JEDNA HLAVNÍ ZMĚNA

Word `0xFE` → `0x3A`. Čtyři datové bajty `1B 00 40 48`.

## OČEKÁVANÝ VÝSLEDEK

`CFG3A ACKAA=01 ACK3A=01 D=01 01 01 01`

## SKUTEČNÝ VÝSLEDEK

UART (`captures/nfc/ov26_exp062_por.bin`):

```text
OpenVusion GU140 EXP-062 v0.11f NFC-D CFG3A
RESET_CAUSE=01
S00 ACKAA=01 ACKF8=01 ACKAB=01 SRAM 00 00 00 00 00 00 00 00
CFG3A ACKAA=01 ACK3A=01 D=01 01 01 01
S01…S08 ACKAB=01 SRAM 00 …
DONE
```

Po POR + lepší TWN4 (UID OK):

```text
config E8 19 00 F8 48   (nezměněno)
session  19 00 F8 48
WRITE 0x40 OK  p40=4F 56 4D 42  p41=01 02 03 04
```

I2C `0x3A` tedy **ACK, ale config EEPROM se nezměnil**. `0x40` je obyčejná user EEPROM (jako SHOW `0x30`), ne SRAM. UART během RF pole garbage.

## KLASIFIKACE

**PASS** — I2C slave ACK na `0x3A` + 4 data.  
**FAIL** — SRAM_MIRROR se nezapnul (`E8` pořád `19 00 F8 48`).  
**PASS** — TWN4 WRITE user `0x40` po přiložení čtečky.

## ZÁVĚR

ACK na `0x3A` ≠ zápis RF config `E8`. Buď Plus 1K chce celý 16 B I2C blok, nebo `0x3A` není ten config blok. SRAM mailbox pořád zavřený.

## DALŠÍ KROK

Jedna změna: I2C write `0x3A` celých 16 B (`1B 00 40 48 08 01 01 00` + nuly), pak peek `E8`. Neopakovat 4B write.
