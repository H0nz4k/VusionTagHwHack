# EXP-064 — 64 B SRAM window F8–FB (RF sequential)

## HYPOTÉZA

S SRAM_MIRROR (EXP-063) NFC stránky `0x40`–`0x4F` jsou 64 B SRAM. RF zápis sekvence `00…3F` se objeví v I²C blocích `F8`–`FB`.

## VSTUPNÍ STAV

EXP-063 PASS (16 B F8). Firmware `v0.11h` dumpuje čtyři SRAM bloky. Config už `1B 00 10 48`.

## JEDNA HLAVNÍ ZMĚNA

MCU čte `F8,F9,FA,FB`. Host `mbox-mirror --phase payload64` (16 stránek).

## OČEKÁVANÝ VÝSLEDEK

UART `F8=00…0F` `F9=10…1F` `FA=20…2F` `FB=30…3F`.

## SKUTEČNÝ VÝSLEDEK

Boot UART: čtyři bloky ACK, nuly. EEPROM `0x10` stále `OVMB`.

První RF payload64: všech 16 stránek readback **PASS** (`nbytes: 64`). Peek `p40=00 01 02 03`.

UART po RF: CP2102 garbage (stejná signatura jako dřív při dlouhém poli). MCU F8–FB z tohoto recapu **nejde** klasifikovat.

064b: `WRITE 0x48 NAK 0x3` — HYPOTÉZA kolize s MCU I²C poll (I2C_LOCKED).

064c: **tři po sobě** payload64 bez reflashe, všechny RF readback 64 B **PASS**. UART po poli dál garbage.

## KLASIFIKACE

| Tvrzení | Výsledek |
|---|---|
| MCU I²C `F8–FB` ACK po POR | **PASS** |
| RF 64 B WRITE + readback | **PASS** (i 3× za sebou) |
| MCU F8–FB == RF po přenosu | **INCONCLUSIVE** (UART garbage); viz EXP-065 |
| NAK 0x48 při souběžném I²C poll | **FAIL** jednou; protokol musí uvolnit I²C |

## ZÁVĚR

RF strana 64 B okna funguje. MCU nesmí pollovat I²C během RF zápisu. Čistý UART dump až po vypnutí pole a I²C-idle okně = EXP-065.

## DALŠÍ KROK

EXP-065: bounded wait bez I²C, pak dump `F8–FB`.
