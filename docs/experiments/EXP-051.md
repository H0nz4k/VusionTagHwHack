# EXP-051 — I2C-clear NTAG dynamic lock, then RF WRITE 0x30

## Hypothesis

PWD_AUTH factory `FFFFFFFF` returned PACK `00 00`, but Type-2 WRITE page `0x30` still NAK `0x0`. That is **lock**, not a wrong password.

NXP NT3H2111: AUTH0 is **byte 3 of page E3**. Peek `E3 = 00 00 00 FF` → AUTH0=`FFh` → password protection **disabled** (AUTH0 > `EBh`). Earlier reading AUTH0 as the first byte was wrong.

Dynamic lock `E2 = FF 3F 7F 00`. Page `0x30` is in the 16-page granularity starting at page 16. NFC cannot WRITE a locked page (NAK 0 / invalid argument). I²C can clear those bits.

## Firmware

`v0.10b_nfc_unlock`. Same SHOW/CoG as v0.10a. At boot: I²C RMW block `0x38` (pages E0–E3), zero E2 lock bytes, keep E0/E1/E3.

## Expected UART

```text
EXP-051 v0.10b NFC UNLOCK
E2=FF3F7F00
UNLOCK WR=01
ARMED
WAIT LED=00
```

Then `ov26-nfc-show.sh 2` → `"written": true`.

## Result

Flashed DEV, isolated. UART **OVĚŘENO**:

```text
EXP-051 v0.10b NFC UNLOCK
RESET_CAUSE=01
E2=00000000
UNLOCK already
ARMED
WAIT LED=00
```

I²C block `0x38` bytes 8–11 already `00`. Did **not** write lock bits (avoided clobbering E0/E1/E3). RF peek still had `E2=FF 3F 7F 00` — I²C vs NFC view mismatch, or peek E2 is a different window.

**AUTH0=FFh** (password off) remains OVĚŘENO from peek. CC page 03 `… 0F` is NFC Forum read-only — candidate if WRITE still NAKs.

Human `ov26-nfc-show.sh 2`: `"written": true` and **new graphics on glass** (command path **PASS**). I²C unlock vs RF `E2` mismatch is secondary.
