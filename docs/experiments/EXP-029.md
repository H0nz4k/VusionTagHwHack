# EXP-029 — Phase H DCDC + first refresh

## Hypothesis

Po EXP-028 (5624+5624) oficiální Pervasive `_DCDC_powerOn` (`0x04`+`0x00`) a `_displayRefresh` (`0x12`+`0x00`) spustí refresh cyklus. BUSY má po `0x12` jít LOW a po dokončení zpět HIGH. Hold ~15 s (2.66") je heartbeat smyčka, ne extra helper.

## Firmware

`v0.4h_refresh` — klon working `v0.4g` + DCDC/REF. `--nooverlay`. Žádný `delay_hold()` (předchozí obrazy: UART garbage od bytu 0).

White fill dle EXP-028: `0x10=0xFF`, `0x13=0x00`. (Pervasive KB: first frame 1=black / 0=white — tento fill je tedy spíš plná čerň; viz klasifikace.)

## UART (`captures/ov26_exp029_por.bin`)

```text
RESET_CAUSE=01
INIT=01
N10=15F8 OK=01 BUSY=1
N13=15F8 OK=01 BUSY=1
DCDC=01 BUSY=1
REF=01 BUSY=0
CHK P0_2SEL=0 CS=1
DONE
HB 00..16 BUSY=0
HB 17..2B BUSY=1
```

1× banner, 1× DONE, 44 HB, žádný reset storm. Isolated GPIO27+21 dh. TAG OFF po capture (e-paper drží).

## Result

**PASS UART/flow.** **STRONG EVIDENCE** refresh cyklu na P1_3:

- po `0x12` okamžitě BUSY=0
- ~17 heartbeatů LOW (~15–18 s při `delay_crude`)
- pak BUSY=1 a drží

To se po `0x00`/`0x0E` (EXP-026) nikdy nestalo.

Vizuál: **OVĚŘENO navazujícím EXP-030** (vlastní B/W pruhy na panelu).

## Klasifikace

PASS (reference flow + smysluplný BUSY cyklus).  
Mapování MOSI/SCLK/DC stále REFERENCE, ale BUSY odpověď na `0x12` je silná evidence, že CoG command path žije.
